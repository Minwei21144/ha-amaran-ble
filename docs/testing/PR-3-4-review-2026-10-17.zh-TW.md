Repository 的外部貢獻核准規則，不授予額外權限，不改寫舊執行結果。

## 程式碼審查

### PR 3 固定色溫能力

- `max_kelvin > min_kelvin` 才提供可調色溫。
- 固定白光且不支援 HS 的燈具使用 brightness 模式，不提供色溫控制。
- 僅支援 HS、但沒有可調色溫的組合仍保留 HS，不誤降成 brightness。
- 數值控制保留既有順序與 unique ID；亮度的內部識別值仍為
  `hsi_intensity`，不因顯示名稱改成「亮度」而改動既有實體識別。
- 清理範圍限於該 config entry 的過期 number 實體；保留仍支援的控制、
  light 實體及其他 config entry。
- 反向或非正數色溫範圍會被拒絕。

### PR 4 預設 GATT 表回退

- 預設表的通知設定出現非逾時、非既有授權錯誤時，丟棄該目標快取並安排
  同一候選的完整探索；不立即交給另一個同樣尚未驗證位置表的候選。
- 回退後實際傳給連線建立器的 `use_services_cache` 為 `False`。
- 完整探索後成功會清理恢復旗標；若仍出現 terminal GATT error，則回到
  既有候選輪次失敗處理，不在這條分支無限重試。
- 原本成功的通知、一般 CCCD timeout 與 insufficient authorization 流程
  保留原行為。錯誤提示表示需要探索，不應視為已證明所有失敗都由位置表造成。
- 不變更 HA Bluetooth、Proxy 韌體、掃描設定或 Mesh 金鑰。

審查與回歸中未發現阻止本次原始碼合併的功能退化。文件合併衝突僅出現在
中英文 changelog 的未發布區段，已保留雙方內容並收斂過度概括的機型描述。

## 驗證邊界

本輪不部署到實際 HA、不重啟 Core、不切換真實燈具，也不修改 automation。
表中數字是使用測試替身的離線測試數，不是實體 BLE 連線輪數或成功率。
PR 作者的 P60x、B7c 與固定白光燈具硬體回報保留於原始 PR，不與本輪
維護者結果混算。多 Proxy、不同無線電環境與長時間實機穩定性仍需另行驗證。

本次處理程式碼合併與 CI，不建立新的 Tag 或 HACS Release。
